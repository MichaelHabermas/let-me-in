🚪 devlog · let-me-in

A door that recognizes you.
No server ever will.

Gatekeeper is a browser-only facial-recognition access control system: webcam in, GRANTED / UNCERTAIN / DENIED out. YOLOv8n face detection and InsightFace embeddings run entirely in-browser on ONNX Runtime Web; enrolled faces live in IndexedDB; nothing leaves the device. This is the log of how it got built — from a week of disposable spikes to a demo-hardened static app.

where it stands

Demo-ready, privacy-intact

Gatekeeper ships as a static site on Netlify — three pages (gate, admin, log), two production dependencies (dexie, onnxruntime-web), zero backend. The gate loop runs camera → worker-side YOLOv8n → crop → embedding → cosine match → three-band policy, with calibrated thresholds an admin can tune and — more unusually — have explained: the calibration UI shows why current thresholds produce the decisions they do.

The final stretch was demo hardening: admin tooltips (Simple → Advanced → Off) enabled in production builds, passive liveness detection landed but parked behind an opt-in flag after its defaults proved too eager, and a sweep/construct gate that proves typecheck + lint + tests + benchmarks in one command.

Gate pipeline: detection, embedding, matching, 3-band verdicts — live
Admin: enrollment, roster import/export, calibration + explainability
Benchmarks with budget checks; accuracy results documented
Passive liveness: shipped, default-off, opt-in flag
WCAG treated as a testable contract (banner contrast test)
No server-side anything — by design, forever
